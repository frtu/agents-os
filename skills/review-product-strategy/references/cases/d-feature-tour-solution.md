# Case D — Feature tour as the solution

- **Before:** a dense UI screenshot; "we have a database of 100k entries"; "soon we will also support A, B and C".
- **Common approach:** add a better screenshot, or a capability matrix.
- **Why this one diverges:** features describe the product; the audience needs the **change in the customer's life**. Future capabilities are discounted to zero — and feel misleading when the listener discovers only the first piece exists.
- **Interrogation:** *"Put today and with-you side by side. Same units: steps, time, accuracy, cost."* (P4). *"Is this built and used today, or planned?"* (P8). *"Can a stranger get this slide at a glance?"* (P10).
- **What surfaces:** the before/after numbers often exist in interviews or pilot data but were never put next to each other.
- **Distilled (what to do):** a side-by-side mirroring the problem slide: "Today: query X databases, Y days, Z% inaccurate. With us: one query, A days, B% accurate — C% more customers verified, D× faster." Replace screenshots with a 3-step bulleted list. Move roadmap to the vision slide, after credibility is earned.
- **Lesson:** show usage and impact, not inventory.
