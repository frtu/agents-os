# Case S — Mid-year feedback as a list of faults

- **Before:** *"Continue: good work. Stop: too much BAU, too slow on hard problems. Start: more visibility."*
- **Common approach:** rating, then strengths, then weaknesses.
- **Why this one diverges:** the same trait is a strength in one context and a cost in another. The explorer "doesn't stay with the baby"; the rigor engineer holds a high bar everywhere. The feedback must be about **balance, not fault**.
- **Interrogation:** *"Which recent example proves each point?"* *"Is this a WHEN problem or a HOW problem?"* (17). *"What part of this is the manager's own doing?"*
- **What surfaces:** business-as-usual load that is healthy because the product is used. Good work kept in the dark. Hard problems carried too long before escalating.
- **Distilled (what to do):** continue = specific behaviors with recent examples. Stop/improve = decompose the WHEN, escalate earlier, move from strict-everywhere to judgement ("lowering the bar is a decision only if a second gate catches it"), make depth visible. Start = measure outcomes, co-build, climb the influence ladder. The manager owns their share. Deliver it before the system does.
- **Lesson:** feedback calibrates a strength; it does not erase it.
