# Worked Case Studies — index

Recurring failure shapes and how the interrogation moves each from weak to defensible. Generic on purpose — pattern-match the shape, not the specifics. **Load the matching case file only when a claim fits its shape** — don't read them all up front.

| Case | Shape to match                                                                            | File                       |
| ---- | ----------------------------------------------------------------------------------------- | -------------------------- |
| A    | Commodity-looking work (migration, upgrade, refactor) claimed by category or output count | `a-commodity-migration.md` |
| B    | A flat list of equal-weight bullets with no thesis                                        | `b-bullet-point-pile.md`   |
| C    | Raw volume (MR count, tickets, hours) offered as proof of seniority                       | `c-effort-vs-seniority.md` |

Each case file carries: **Before** (the weak claim) → **Interrogation** (the challenge to fire, with heuristic numbers) → **What surfaces** → **Distilled** (the defensible form) → **Lesson**.

## Growing the case library

When you hit a **new failure shape** during a review — one that recurs and isn't captured by any case above — capture it here so future runs reuse it, **without touching SKILL.md**:

1. Confirm it's genuinely new (not a variant of an existing case) and worth reusing.
2. Write a new file `{next-letter}-{short-name}.md` in this folder, following the same frontmatter (`case`, `name`, `shape`, `heuristics`) and Before → Interrogation → What surfaces → Distilled → Lesson structure.
3. Add one row to the index table above.
4. Keep it **generic** — no real names, projects, or numbers; genericize the specifics into a reusable pattern.
