# Cases — registry

Worked runs of this skill. Each case records the real lane plan, the gate findings and the lessons
learned. Match the user's ask to a case shape and load **only** that case, as a model for `plan.json`.

| Case | Shape                                                                                                                                               | Phases                                 | File                                                                       |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------- |
| A    | Personal/team contribution sources plus a resume → member, feature, pattern and source pages → evidence map → resume review through a director lens | 1 (4 lanes) · 2 (2 lanes) · 3 (1 lane) | [a-contribution-to-resume-review.md](./a-contribution-to-resume-review.md) |

## Adding a case

1. After a run, copy the final `plan.json` lanes as a compact table: lane → scope → number of creates → template.
2. Record the gate findings that needed action, and how each was fixed.
3. Record 3–6 lessons. When a lesson recurs across cases, promote it into `orchestration-plan.md`
   or `lane-catalog.md` as a generic rule.
4. Add a row above. Leave `SKILL.md` unchanged unless the process itself changed.
5. Specific names, numbers and vault paths may appear in a case. Point to the vault's log entry for the full
   list of pages, rather than copying it.
