# Retro formats → template mapping

Teams run retros in many board formats. The report always uses the same spine (`retrospective-report.md`); this file says where each board column lands. Read it in **Step 1** when the raw input isn't already in Went well / Needs improvement / Start-Stop-Continue form.

## Mapping table

| Format | Columns | → Went well (§4) | → Needs improvement (§5) | → Risks to watch (§5b) | → Start/Stop/Continue (§6) / actions (§7) | Worked case |
|---|---|---|---|---|---|---|
| **Start / Stop / Continue** | Start, Stop, Continue | Continue (the evidence behind it) | Stop (the pain behind it) | — | Start, Stop, Continue | — |
| **Went well / To improve / Actions** | 3 columns | Went well | To improve | — | Actions (rewrite: most restate the problem) | A |
| **Goal-framed** | Goal, Went well, Improve, Action plan | Went well | Improve | — | Action plan. **Goal → Summary must answer it** | B |
| **Sailboat** | Island, Wind, Anchors, Rocks (sometimes Sun) | Wind (+ Sun) | Anchors | Rocks | from voted Anchors/Rocks. **Island → Summary direction** | C |
| **WRAP** | Wishes, Risks, Appreciations, Puzzles | Appreciations | Risks already hurting; pain implied by Wishes | Risks not yet hurting | Wishes → Start; **Puzzles → decision + owner + date** | D |
| **4Ls** | Liked, Learned, Lacked, Longed for | Liked | Lacked; pain implied by Learned | — | Learned → candidate actions; Longed for → Start | E |
| **Feedback grid** | Worked well, To change, Questions, Ideas | Worked well | To change | — | Ideas → Start; Questions → decision + owner | — |
| **Three little pigs** | Straw house, Wood house, Brick house | Brick (stable) | Wood (minor) | Straw (fragile — could fail any time) | from Straw first | — |
| **Mountain / climb** | Sun, Climbing, Weeds, Storm, Falling | Sun | Storm (unclear/challenges) | Falling (risks) | Climbing → Continue; Weeds → Stop | — |
| **Hot-air balloon** | Sunny days, Sandbags, Storm | Sunny days | Sandbags | Storm | from Sandbags/Storm | — |

## Rules that apply to every format

1. **Recover the pain behind the wish.** A Wish, Longed-for, or Learned sticky implies a current problem. Put the problem in §5 (symptom → impact → cause) and the wish in §6/§7.
2. **Risks are not pains.** Something that *could* hurt goes to *Risks to watch* with an early signal and an owner; only the top one or two become actions.
3. **Votes set priority.** The highest-voted items must reach the action table or be **explicitly parked** with a reason. Comment counts on a sticky mean there's detail to read before writing.
4. **Refile misfiled stickies.** An appreciation posted as a wish, a question posted as an appreciation — move it; don't let the column decide its meaning.
5. **Separate deliberate wins from luck.** "Weather was perfect" is not a practice to repeat — it's a risk to plan for.
6. **Metaphor goals are direction, not actions.** The Island / Goal feeds the summary; if there are several, keep the one that can steer trade-offs.
7. **Appreciations may name people.** Blameless applies to problems, not thanks.
8. **Board formats rarely capture numbers.** Every format needs the same follow-up question: *what's the number behind the headline?*
